# Colibri: Running 744B-Parameter MoE Models on Consumer Hardware Changes the Local AI Equation

Colibri, a pure C inference engine from Italian developer JustVugg, runs Z.ai's GLM-5.2 — a 744-billion-parameter Mixture-of-Experts model — on a consumer machine with roughly 25 GB of RAM by streaming experts from NVMe disk on demand. This is not a distilled or quantized-down version; it runs the full frontier model weights locally, shifting the bottleneck from memory capacity to disk throughput and making "AI sovereignty" practical for individuals and small teams without datacenter infrastructure.

## What Colibri Is and Why It Matters

Colibri is an inference engine written in C under the Apache 2.0 license with zero external dependencies — no BLAS, no Python runtime, no PyTorch. It treats VRAM, system RAM, and NVMe storage as a single unified memory hierarchy. The dense components of GLM-5.2 (approximately 17 billion parameters, ~9.9 GB in int4 quantization) remain resident in RAM. The 21,504 routed experts comprising the bulk of the model (~370 GB on disk in int4) are streamed from NVMe on demand with a per-layer LRU cache and a learned pinned hot-store. The result: a 1.5 TB model runs on a mid-range PC with 25 GB RAM, 12+ cores, and a large NVMe SSD.

This approach reframes the local AI constraint. Traditionally, running a model required the full weight set in VRAM or RAM — a hard wall. Colibri makes RAM a continuous speed spectrum: more fast memory yields higher tokens per second; less yields slower but functional inference. For batch workloads, patient reasoning agents, or sovereignty-critical deployments, this trade-off is exactly the right one.

## The Model: GLM-5.2 at 744B Parameters

GLM-5.2, released by Z.ai (formerly Zhipu AI) in June 2026, is a Mixture-of-Experts model with approximately 753 billion total parameters and ~40 billion active per token. It features a 1-million-token context window, mandatory reasoning with adjustable effort levels, and an MIT license permitting commercial use, modification, and redistribution. Independent benchmarking by Artificial Analysis scores GLM-5.2 at 51 on their Intelligence Index — the highest of any open-weight model and fourth overall behind only Claude Fable 5 (60), Claude Opus 4.8 (56), and GPT-5.5 (55). It ranks second on Code Arena for frontend development tasks.

The model weights are roughly 1.5 TB in BF16 (~750 GB in FP8), conventionally requiring 8 H200 GPUs for FP8 inference. Colibri's achievement is running the same weights on consumer hardware through expert streaming rather than quantization alone.

## How Expert Streaming Works

Mixture-of-Experts architectures activate only a small subset of experts per token. GLM-5.2 routes each token through approximately 5.4% of its parameters (~40B active of 744B total). Only ~11 GB of experts change from one token to the next. Colibri exploits this sparsity by keeping dense layers resident and fetching only the routed experts from disk per token.

The engine combines several techniques: compressed KV cache with Multi-latent Attention (576 values per token vs. 32,768), native speculative decoding with multi-token prediction (community-measured at 2.2–2.8 tokens per forward pass), quantized int8/int4/int2 kernels with optional CUDA and Metal backends, KV-cache persistence across restarts, grammar-forced structured output, and an OpenAI-compatible API server. Performance ranges from 0.3 to ~1.2 tokens per second depending on hardware — not interactive chat speed, but practical for batch processing, long-horizon agents, and offline sovereignty use cases.

## The Research Context: MoE on Edge Hardware

Colibri's approach aligns with a growing research recognition that MoE models face different bottlenecks on consumer hardware than in datacenters. A 2026 empirical study from the Analytics Everywhere Lab benchmarked OLMoE-1B-7B (1.3B active of 6.9B total) against dense baselines on an Apple M2 Pro and NVIDIA Jetson Orin Nano 8GB. The study found that on bandwidth-bound edge hardware, inference cost tracks total parameters, not active ones. OLMoE's active-parameter advantage was only partially realized on the M2 Pro (~10% behind Llama-3.2-1B at matched active count) and eroded on the Jetson Orin Nano (~31% behind, at 2.1x the energy per token with peak memory at the 8GB ceiling).

The study concluded that routing arithmetic is not the bottleneck — memory bandwidth is. MoE models still require the full weight set in memory because the router cannot predict the next token's expert assignment ahead of time. Colibri's disk-tier approach directly addresses this by accepting the bandwidth constraint and optimizing the streaming path instead: batched expert unions, overlapped reads and compute, `O_DIRECT` I/O, and weighted dual-SSD striping.

## Hardware Requirements and Practical Deployment

Colibri's stated minimums are modest for the model scale: ~25 GB RAM, 12+ CPU cores, and a large NVMe SSD (the int4 model requires ~370 GB). The engine supports multiple GPU backends: CUDA for NVIDIA, Metal for Apple Silicon, and an experimental Vulkan backend for AMD and older GPUs via Mesa/RADV. A resident CUDA pipeline option keeps the residual stream on-device across layers so the CPU expert loop runs uninterrupted.

The project has accumulated ~25,600 GitHub stars and 2,800 forks as of late August 2026, with 1,666 commits. Six model families are supported: GLM-5.2 (744B), Inkling (975B), Kimi K3 (2.8T), DeepSeek V4 Flash (284B), Qwen3.6 (35B-A3B), and OLMoE (7B) — each with a single C file frontend sharing the same `coli chat` / `coli serve` / `coli web` interface.

## Visualization and Observability

Colibri includes a web dashboard (`./coli web`) showing live token metrics, per-turn time breakdowns, VRAM/RAM/disk tier bars, and a "mini-brain" visualization. The Brain page renders all 19,456 experts as a living cortex — color indicates storage tier, brightness shows routing heat, and every expert routed in a turn flashes white. The Atlas page maps 13,260 characterized experts as a 3-D galaxy, with 1,041 replicated specialists clustering by measured topic affinity (poetry, law, Chinese, SQL, etc.) based on routing patterns, not learned embeddings.

## Implications for AI Sovereignty and Access

The practical consequence is accessibility: a frontier open-weight model that runs on owned hardware, without depending on an API that can be throttled or switched off. This connects directly to the AI sovereignty argument — when a government can order the shutdown of a commercial model overnight (as occurred with Claude Fable 5), locally held weights are not exposed to that decision. Running GLM-5.2 locally means prompts, context, and data stay on your infrastructure with no cross-border transfer, no sub-processor vetting, and no Entity List complications.

The MIT license on GLM-5.2 imposes no regional or use restrictions. For EU organizations, self-hosting avoids GDPR Article 44 transfer assessments and DPIA requirements that apply when routing data to Z.ai's China-hosted API (subject to China's National Intelligence Law and PIPL). Zhipu AI's presence on the US Department of Commerce Entity List since January 2025 adds further due-diligence weight to the local-weights choice.

## Limitations and Honest Trade-offs

Colibri is slow (0.3–1.2 tok/s), needs 370 GB of fast disk space, is a young community project, and remains tied to the availability of the quantized GLM-5.2 checkpoint. It is not a model for fluid interactive chat. The Tom's Hardware community notes that int4 quantization loses quality, and older Xeon servers with cheap DDR3 and used GPUs may achieve better price/performance for near-frontier MoE models at 1-2 tokens/second. AMD's upcoming Epyc Venice with 16 memory channels and MRDIMMs (~1.6 TB/sec bandwidth) could make CPU inference on large MoE models considerably more usable.

The empirical study on OLMoE confirms the core tension: on bandwidth-bound hardware, sparse activation does not deliver the edge-inference advantage it promises. The open question for future MoE design is whether sparse-activation quality gains with hardware-aware routing can offset the memory-footprint overhead. Colibri's contribution is proving the disk-tier approach works today, with the engine deliberately small enough that the next optimization can come from anyone willing to measure it.

## The Broader Local AI Movement

Colibri sits alongside antirez's DwarfStar 4 (which made KV cache a disk citizen) and NVIDIA's GB10 workstations as different pieces of the same movement: carrying frontier models from the cluster to the desk. The open-weight ecosystem — GLM-5.2, DeepSeek V4, Qwen, Gemma — creates a plurality of downloadable, competitive models that hedges against any single provider's kill-switch. Tools like vLLM, Ollama, LM Studio, and now Colibri form the runtime layer that makes local ownership operational.

For organizations with compliance, data-residency, or sustained-throughput requirements, self-hosting earns its keep. For individuals, it shifts AI from a rented service to a owned capability. The trajectory is clear: AI is too critical to be only a provided service. A frontier model that runs under your desk today takes RAM, a large SSD, and patience — but it runs.
